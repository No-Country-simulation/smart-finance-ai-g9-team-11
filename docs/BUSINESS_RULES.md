# Business Rules

## Overview

This document describes the business rules implemented by the Finance AI platform.

The objective of the system is to analyze a user's financial behavior using Machine Learning and provide personalized financial insights based on the information provided, supported by a local fallback mechanism when the external service is unavailable.

---

# Business Flow

The financial analysis follows the process below.

```
User

    │

    ▼

Submit Financial Information

    │

    ▼

Backend Validation (Authentication, Constraints)

    │

    ▼

Store Analysis Request

    │

    ▼

Send Data to Machine Learning

    │

    ▼

[Success] Machine Learning Prediction / [Failure] Local Fallback Calculation

    │

    ▼

Store Analysis Result (with Source Origin: ML or FALLBACK)

    │

    ▼

Return Response

```

---

# Financial Analysis

A financial analysis consists of evaluating a user's financial situation based on the following information:

* Monthly income
* Debt level
* Saving frequency
* Financial transactions

These data are processed by the Machine Learning model or by local heuristic rules during a fallback to generate a financial profile.

---

# Request Validation

Before processing the analysis, the backend validates the request.

Validation rules include:

* Required fields
* Numeric values greater than or equal to zero
* Valid enumeration values
* Valid transaction list
* Resource ownership validation via user ID to prevent unauthorized access
* Business window rules (e.g., preventing edits or deletions on transactions older than 30 days)


* Prevention of duplicate transactions



Requests that fail validation are rejected before reaching the Machine Learning service.

---

# Transaction Classification

Transaction classification is performed by the Machine Learning service or through a local keyword-matching fallback mechanism if the external service is unavailable.

Example:

```
Input

"Supermercado"

↓

Machine Learning / Fallback

↓

ALIMENTACAO

```

The system tracks whether the classification originated from the ML model or the local fallback via the source origin field.

---

# Spending Summary

The spending summary is generated by the Machine Learning service or computed locally by grouping transaction values by category during a fallback scenario.

Example:

Transactions

```
Supermercado     420

Restaurante      80

Combustível      300

```

Generated summary

```
ALIMENTACAO → 500

TRAJETO → 300

```

The backend processes and returns this information.

---

# Financial Profile

The financial profile is predicted by the Machine Learning model or calculated deterministically by comparing total revenues and expenses during fallback conditions.

Possible values:

```
SAUDAVEL

EM_RISCO

EM_OBSERVACAO

```

The prediction considers multiple financial variables simultaneously.

---

# Prediction Confidence

Along with the financial profile, the model returns a confidence score.

Example

```
Profile

EM_OBSERVACAO

Confidence

0.82

```

This value represents the confidence level of the prediction. During local fallback executions, this value defaults to zero.

---

# Financial Recommendations

Recommendations are generated dynamically by the Machine Learning model or provided as a generic notification regarding service unavailability during fallback.

Example

```
Increase monthly savings.

Reduce entertainment expenses.

```

Recommendations are generated according to the predicted financial profile.

The backend does not create or modify recommendations.

---

# Persistence

The backend is responsible for persisting financial analyses.

The following information is stored:

* User financial information
* Financial profile
* Prediction confidence
* Transactions
* Analysis date
* Source origin (`ML` or `FALLBACK`)



Recommendations are currently **not persisted**.

---

# Saving Frequency

Saving frequency can be provided or calculated based on the surplus percentage (Revenues minus Expenses) relative to total revenues during fallback processing.

Possible values:

```
BAIXA

MEDIA

ALTA

```

The backend validates the value before processing it.

---

# Debt Level

The debt level can be provided by the client application or calculated automatically by the backend as a percentage ratio between expenses and revenues during fallback operations.

The backend validates the received value and forwards it or processes it accordingly.

---

# Transaction Categories

Transaction categories are inferred automatically by the Machine Learning model or through local fallback keyword matching.

Current categories include:

* ALIMENTACAO
* MORADIA
* UTILITARIOS
* INVESTIMENTO
* COMPRAS
* SAUDE
* ENTRETENIMENTO
* TRAJETO
* SALARIO
* OUTROS

The client application never sends transaction categories.

---

# Backend Responsibilities

The backend is responsible for:

* Validating requests
* Persisting analyses
* Calling the Machine Learning service
* Managing local fallback mechanisms for classification and profiling
* Returning responses
* Managing database versioning with Flyway
* Handling user account lifecycles (including soft deletes)


* Enforcing security and multi-tenant data isolation

---

# Machine Learning Responsibilities

The Machine Learning service is responsible for:

* Classifying transactions
* Predicting the financial profile
* Calculating prediction confidence
* Generating recommendations
* Building the spending summary

---

# Database Rules

Database schema changes must always be performed through Flyway migrations.

Manual changes to production databases are not recommended.

---

# Error Handling

If the Machine Learning service is unavailable:

* The backend catches the external service exception and invokes local fallback mechanisms.


* The failure is logged.


* Fallback-generated analyses are persisted with appropriate source indicators without interrupting the user experience.
